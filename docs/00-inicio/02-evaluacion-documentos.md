# Evaluación de documentos previos

## Criterio utilizado

Se compararon los tres archivos recibidos con el anteproyecto. Se distinguen cuatro
estados:

- **Integrar:** compatible y útil como base documental.
- **Integrar con revisión:** útil, pero necesita validación o ajuste de alcance.
- **Mantener como evidencia de campo:** no debe convertirse en requisito todavía.
- **No usar como hecho:** contradice otra fuente o contiene una afirmación que requiere
  evidencia formal.

## `Antecedentes.md`

### Valor

Es necesario como descripción operativa preliminar. Aporta información que el
anteproyecto resume, pero que puede servir para preparar entrevistas, observación y
requerimientos: productos, equipamiento, mingas, asistencia, acopio, secado, pesaje,
residuos, inventario, ventas, pedidos y presencia digital.

### Tratamiento

**Integrar con revisión**, no como requisitos definitivos.

### Datos que requieren confirmación

- Denominación legal: utiliza “Asociación” y el título del anteproyecto utiliza “Comité”.
- Lista actual de productos y presentaciones.
- Existencia y estado de cada equipo.
- Estado y uso real de las dos computadoras; el anteproyecto las registra como recursos
  operativos existentes, mientras este archivo dice que no se usan.
- Existencia del software de facturación.
- Existencia de sanciones económicas y reglas para aplicarlas.
- Distribución del stock entre pedidos institucionales y venta individual.
- Fórmula de costo, margen organizacional y ganancia individual.
- Meses de mayor demanda: abril, noviembre y diciembre.
- Compra a productores locales y proveedores externos.
- Registro sanitario de todos los productos; requiere evidencia documental.
- Estado real del sitio web y necesidad de integrarlo al alcance.

### Correcciones editoriales pendientes

El documento debe corregirse después de validar los datos: “actividades”, “computadoras”,
“secado”, “envasado” y redacción de frases incompletas.

## `Definición del problema..md`

### Valor

Es necesario para formular el problema y preparar el levantamiento de requerimientos.
La versión causa → síntoma → efecto es útil para el análisis, pero no debe reemplazar la
formulación oficial del anteproyecto.

### Tratamiento

**Integrar con revisión.** Se conservará una sola formulación principal y las demás
versiones quedarán como borradores de trabajo.

### Ajustes necesarios

- Mantener como problema central la gestión organizacional, el control de asistencia y la
  trazabilidad productiva.
- Tratar ventas, cuentas por cobrar y sitio web como alcance por confirmar, aunque el
  anteproyecto los menciona en módulos o justificación.
- No afirmar sanciones económicas imprecisas hasta confirmar su existencia y reglas.
- Separar problema principal, causas, síntomas y efectos.

## `Metodología.md`

### Valor

Es necesaria y compatible con el anteproyecto. Sirve como borrador de metodología, pero
debe reorganizarse para separar investigación, desarrollo de software y evaluación.

### Tratamiento

**Integrar con ajustes.** La metodología base se documenta en:

[[../metodologia/METODOLOGIA-BASE|Metodología base del proyecto]].

### Ajustes necesarios

- Mantener investigación aplicada y de campo.
- Mantener enfoque cualitativo con apoyo cuantitativo, siempre que se recojan y analicen
  ambos tipos de datos.
- Mantener el método analítico-sintético.
- Mantener observación directa y entrevista semiestructurada como técnicas principales.
- Tratar la matriz de requerimientos y los diagramas como productos de ingeniería, no como
  técnicas de recolección de datos.
- Nombrar explícitamente Scrum, porque es la metodología indicada en el anteproyecto.
- Separar pruebas funcionales y pruebas con usuarios de las técnicas de investigación.
- Usar UML como base confirmada; BPMN queda opcional hasta que la directora lo apruebe.

## Resultado

| Archivo | Decisión |
|---|---|
| `Antecedentes.md` | Integrar como evidencia de campo pendiente de validar |
| `Definición del problema..md` | Consolidar y ajustar al alcance del anteproyecto |
| `Metodología.md` | Integrar con separación metodológica y Scrum explícito |

No se inicia ningún sprint con esta revisión. Solo se actualiza la base documental.
